# Mekiki Map

AI にどこまで任せ、何を自分でやるか。仕事や学びの場面に当てはめて考え直すための枠組み（Mekiki Framework）と、その案内図です。

地図を開く：https://mekiki-framework.github.io/map/

English: https://mekiki-framework.github.io/map/en/

## 何のための枠組みか

AI でできることは増え、手間も減ったのに、どこかで噛み合わなくなる。AI の精度の問題か、使い方の問題か、それとも、人の側に残るはずの何かが抜けているのか。ここでは、その三つ目を自分の状況に照らし合わせて確かめられます。

五本の論文を一気に読むのは、かなりの負担になります。私自身、全体のあちこちを行き来するのは大変です。AI が論文を正確に参照できる仕組みは GitHub と Mekiki Reader に整えてありますが、まずは人が全体を見渡して、自分の関心に近いところから入っていける入口がほしいと思い、この地図を作りました。

想定しているのは、仕事や学びの場で AI を使い始め、便利になった一方で「なんだか噛み合わない」「どこまで任せていいのか分からない」と引っかかりを覚えている人です。研究者や専門家だけでなく、現場で手を動かしている人や、ものを作っている人にも使える枠組みだと考えています。

一番の使い道は、自分の場面に当てはめて「その状況で、どこを考えればいいのか」を見つけることです。その先には、さらに二つの使い方があります。気になった箇所があれば、論文の原文で確かめられます。また、AI と一緒に何かを考えるときには、話が「AI が賢いかどうか」という一本の軸に流れてしまわないための、道標にもなります。私自身も、そう使っています。

なお、この地図は論文の代わりになるものではありません。また、この枠組みも、AI 活用の正解やノウハウを集めたものではありません。自身の状況を整理し、見直す手がかりにはなりますが、答えを出したり、判断を代行したりはしません。最後に残るのは、誰かを評価する答えではなく、次に立ち止まって考える場所です。個別の判断は、たどる人自身の手に残ります。

## 入り方

- **自分の場面に当てはめて読む**　五本の論文を、身近な場面に当てはめて読む例です。場面ごとに問いがいくつかあり、いちばん近い答えを選ぶと、次の問いか、最後に残る問いに進みます。残る問いは評価ではなく、次に考える場所を示します。
  - どこまで任せ、何を自分で決めるか（AI に任せる・全 5 問）
  - AI のほうが上手いことを、自分で続けるか（あえて自分でやる・全 3 問）
  - AI で良いものができた。それで学べたと言えるか。（学ぶ・教える・全 4 問）
  - ベテランの判断を次の人へ渡す（技術伝承・全 8 問）
  - 降りてきた仕事を、自分のこととして受け取れるか（職場で・全 4 問）
- **五本の論文が言っていること**　一本につき一段落です。
- **地図で読む**　五本の区別とそのつながりを、一枚に置いた図です。原文と照らして確かめられます。

## 作り方

原文の引用は、原文と一字ずつ照合してあります。要約、名前、配置は、AI を使って作り、著者が確認しました。英語のページは、著者が確認した日本語のページを、AI を使って訳したものです。二つが食い違うときは、日本語が基準です。この地図は派生した案内図で、論文の代わりにはなりません。
